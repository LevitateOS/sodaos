# SodaOS library-reuse investigation

This is the completed non-normative investigation at the revisions below. The [library-adoption chapter](../development/ideal-filetree-plan/library-adoption.md) owns the selected execution sequence; the [research coverage ledger](library-reuse-coverage.md) records evidence scope. Original probes, source census and checkpoint captures remain in the adjacent project output directory.

The strongest direction is to remove complete generic engines: HTTP framing, WebSockets, PostgreSQL connection/query orchestration, handwritten hash/curve math, Rust JSON syntax/binding, and repeated Base64 implementations. Keep Soda's authority and admission rules as small explicit adapters. Delete unnecessary SQL translation and compatibility diagnostics; consolidate existing library-backed archive, bounded I/O and filesystem mechanics. A few narrow predicates and byte-preserving policies should remain custom. Forgejo effective configuration has one precisely stated evidence blocker rather than an unqualified parser recommendation.

This is an investigation only. No production implementation, dependency manifest/lock, language boundary or ideal-filetree plan was changed. Recommendations run inside existing processes; they do not introduce sidecars. PostgreSQL is the product database. Multiple provider credential/execution contracts and deliberate Forgejo template overrides remain authoritative. Older dependency-free/offline/Go-equivalence comments and tests were examined as claims, not treated as owner requirements.

## Dependency/build/offline conclusions applying to every finding

`Cargo.toml` explicitly permits online builds, keeps `Cargo.lock` committed and forbids vendoring. `rust-toolchain.toml` selects **stable**, not a numeric pinned Rust release; Go is pinned to **1.26.7**, and the local SDK module declares a 1.26.0 minimum. Do not describe Rust as numerically pinned until release tooling supplies a concrete compiler record. Existing RustCrypto, Serde, Base64, tar/flate2, url, getrandom and libc dependency families already refute a repository-wide “dependency-free” rule.

Release compilation in `lib/soda-release-build/src/production_compile.rs::compile_rust` invokes `cargo build --release --locked --manifest-path … -p …`, then copies/chmods/checks the resulting executable. Candidate setup builds controller binaries with Cargo too. [tools/candidate-setup/src/worker_caches.rs](../../tools/candidate-setup/src/worker_caches.rs) warms Go/Bun caches and sets the worker's Go proxy to off; its inspected path does **not** demonstrate a complete Rust Cargo cache for the final worker identity/target/features. Worker/build environment allowlists constrain which cache variables reach children. A comment that a worker has no network is not, by itself, evidence of the complete installed network policy or cache closure.

Before library adoption, resolve and commit the intended graph in an authorized implementation pass; record a concrete Rust compiler, platform and feature selection; prefetch using the admitted setup identity/cache path; then prove `--locked --offline` builds for every shipping target/package in the actual worker environment. Do not vendor or fetch dependencies at appliance runtime. Cargo's explicit fetch/offline model supports library reuse with staged caches; offline is a packaging task, not a reason to maintain protocols or crypto primitives. [Cargo fetch and offline behavior](https://doc.rust-lang.org/cargo/commands/cargo-fetch.html).

Local registry presence was checked read-only. Sources for base64 0.22.1, serde 1.0.229, serde_json 1.0.151, sha2 0.10.9/0.11.0, postgres-protocol 0.6.12, rustix 1.1.5 and x509-cert 0.2.5 were present; absence from that source listing is not proof of cache absence elsewhere. The focused crypto probe built its small selected graph offline, which proves only that graph in this environment. No proposed Hyper/Postgres/tungstenite/Clap/time/tempfile graph was qualified as an offline release build. License statements below describe selected upstream crates; implementation must also check resolved transitive licenses and notice obligations. Versions are preferred concrete selections researched during this pass, not a recommendation to follow unpinned `latest`.

Net LOC and effort estimates exclude tests, overlap between findings and are not additive. Deletion of generic code does not justify deletion of product policy or its acceptance tests. Folder moves, filetree regeneration and unrelated ports are outside every backlog item.

### N1 — complete HTTP servers, with explicit Unix custody

Defining code is [host daemon/http.rs](../../lib/host/src/daemon/http.rs), [response.rs](../../lib/host/src/daemon/response.rs), [routes.rs](../../lib/host/src/daemon/routes.rs), [gmux_server.rs](../../lib/host/src/gmux_server.rs), and identity [http_wire.rs](../../cmd/soda-identity/src/http_wire.rs), [http.rs](../../cmd/soda-identity/src/http.rs), [http_routes.rs](../../cmd/soda-identity/src/http_routes.rs). The active host chain is `lib/host/src/main.rs → gmux_server::Server::serve → handle_conn → daemon::http::read_request → daemon::routes dispatch → dbackend::RuntimeBackend/project/terminal/tailnet backends`. Identity is `cmd/soda-identity/src/main.rs → admin/runtime Listener and Server → handle connection/read_request → route_request → Controller`. `gmux_*` facade modules remain active adapters, not a second complete HTTP implementation.

Host `read_request` scans bytes until CRLFCRLF, splits the request line, parses headers, allocates a capped body and manually interprets Content-Length. It checks a third request token exists but does not validate the HTTP version or complete method/request-line grammar. Transfer-Encoding rejects exactly `chunked`, while other values are ignored. A header containing `gzip, chunked` is therefore treated differently from `chunked`. Duplicate Content-Length is rejected even when identical. Host body limits are derived from the selected route; terminal GET skips the body. These details establish an incomplete protocol engine; fixing each individual condition would retain the broader maintenance burden. The response owner manually assembles status/header/body framing, and tailnet_response edits the serialized header bytes to insert no-store.

The existing 5-second header and 30-second body socket settings are inactivity limits on blocking operations. They do not establish a total header/body duration. The server accepts on a nonblocking listener, sleeps 50 ms when idle, and spawns a thread per accepted connection. `inflight` increments and decrements manually rather than holding an RAII connection token. The mutation gate and terminal slot are real application ownership, not HTTP protocol work. Identity repeats the engine; it records query/origin as strings, so bare `?` and an empty Origin header pass its nonempty checks whereas host admission records their presence. Source inspection does not establish these accidental divergences as an intentional security contract.

The actual requirement is legal HTTP/1 framing from current Go net/http peers, bounded memory/time, correct response bodies/statuses, each private socket's actual admission before privileged routing, serialized mutations, and definitive shutdown/custody. It is not exact malformed-input acceptance or Go status wording. The existing Go dashboard operator and extension servers already delegate to net/http. [cmd/soda-dashboard/operator_linux.go](../../cmd/soda-dashboard/operator_linux.go) uses `SyscallConn.Control` for kernel peer UID admission; retain that adapter (and its test showing why `UnixConn.File()` must not change blocking ownership).

Preferred replacement is Hyper 1.12.0 HTTP/1 with hyper-util 0.1.21 TokioIo/TokioTimer and Tokio 1.53.2. Hyper is a complete request/response framing owner; httparse alone parses the header syntax and leaves body framing, chunk handling, EOF, lifecycle and response output in Soda. A parser-only migration is therefore insufficient. Hyper exposes exact maximum header bytes and a timer-backed whole-header deadline; configure explicit values because upstream builder defaults are not stable. [Hyper 1.12.0 builder documentation](https://docs.rs/hyper/latest/hyper/server/conn/http1/struct.Builder.html), [hyper-util 0.1.21 features](https://raw.githubusercontent.com/hyperium/hyper-util/v0.1.21/Cargo.toml).

The adapter must be concrete:

- Consume systemd fd3 exactly once after current LISTEN_PID/FDS/root checks. Identity still consumes the named admin/runtime fd3/fd4 pair and checks paths/permissions. Do not create substitute listeners or transfer a raw descriptor twice.
- Apply each socket's actual authorization before routing/conversion: host HTTP relies on root-owned filesystem/systemd socket access (its exported peer helpers have no production callers), identity keeps admin/runtime path and permission authority, and Go operator retains kernel peer UID admission. Muse's separate packet socket retains its SO_PEERCRED/SO_PEERPIDFD pin. Do not add a universal UID gate or weaken any existing one. Keep existing directory/socket ownership and fixture exposure policy.
- Start one runtime inside the existing service, with only needed HTTP/1, net, time, sync and runtime features; do not create a sidecar. Use a bounded blocking-worker interface for existing synchronous Backend/Controller calls. A blocking Mutex acquisition on the I/O thread can wedge every connection, so gate acquisition/backend work belongs in this worker boundary.
- Set header size 8,192 bytes for current private servers, disable keep-alive (one-operation connection contract), set header_read_timeout(5 s) with TokioTimer, and consume streaming bodies up to the route cap plus one. Decide explicitly whether a 30-second total body deadline replaces the present inactivity bound; report the strengthened behavior instead of claiming equivalence.
- Encode response bodies and application headers as typed HTTP responses. Keep content type, nosniff error headers, tailnet no-store, native/identity newline envelopes and status mapping. Automatic Date/header case differences are not product changes unless an external contract is found.
- Hold an RAII inflight token through an upgraded WebSocket session, not only through the HTTP response. Propagate service shutdown to active sessions and backend cancellation, wait within the existing service budget, and join task/child cleanup before returning ownership.

The WebSocket handoff needs particular care: recover the original `TokioIo<tokio::net::UnixStream>` from Hyper Upgraded using its typed downcast/parts mechanism, preserve its read-ahead bytes, return the stream to std ownership and pass those bytes to tungstenite::WebSocket::from_partially_read. Merely extracting a file descriptor or constructing from_raw_socket loses early client frames. This API path was checked in upstream documentation, but not compiled with Soda's exact service adapter; a focused integration spike is a migration acceptance step, not completed validation here.

Relevant tests are host gmux_smoke HTTP/admission/upgrade/shutdown assertions, host dbackend frame tests, identity http_tests and integration tests/http.rs, and Go operator_linux_test.go. Their route caps, status/error secrecy and custody cases are real requirements. Their assertion that a request lacking Sec-WebSocket-Version must upgrade is an obsolete parser behavior. Add independent framing cases: CL/TE ambiguity and malformed duplicate fields, complete valid chunk/EOF responses, oversized headers/trailers, slow trickle versus total deadline, request-target percent escapes, empty Origin/query presence, panic/error inflight release, admission before dispatch, and shutdown with live terminal/client/worker. Source/test inspection only; no server test suite or installed service was run.

Runtime/build: these are in-process Rust libraries. Hyper/hyper-util/Tokio are MIT; hyper-util 0.1.21 requires Rust 1.85 and Tokio 1.53.2 advertises 1.71. The local probe compiler is Rust 1.99.0, not proof of each artifact toolchain. New dependency resolution and artifact cross-build/size verification are needed. Exact Hyper package MSRV was not independently recovered from its tagged manifest, so artifact toolchain validation remains an acceptance prerequisite rather than an invented number. [Tokio 1.53.2 manifest](https://raw.githubusercontent.com/tokio-rs/tokio/tokio-1.53.2/tokio/Cargo.toml).

The Go sibling `internal/host/client.go::NewClient/callLimit` already uses net/http over a Unix DialContext with no redirects and bounded io.LimitReader; retain it. Source comments preserving what current Rust servers happen to emit do not justify a partial client protocol engine. Current peers and their upgrades can legally use chunking or EOF framing. Error/status secrecy and endpoint limits remain Soda's responsibilities.

REPLACE these engines with one Hyper 1.12.0 HTTP/1 client transport boundary; keep the caller facade synchronous. The transport owns a Unix connection, drives its connection future concurrently while sending and consuming the response, explicitly configures client max_buf_size/max_headers and body caps, consumes only cap+one before rejecting, and closes/cancels the connection at the operation deadline. The client builder exposes max_buf_size (minimum 8,192) and max_headers rather than the server exact max_header_size API; preserving a stricter exact byte cap, if required beyond its bounded header buffer, needs a focused checked transport admission design rather than an invented builder method. Driving only send_request without the connection future is a deadlock. [Hyper client builder](https://docs.rs/hyper/latest/hyper/client/conn/http1/struct.Builder.html). No automatic retry of POSTs/credential deliveries: outcome uncertainty is a domain contract. Validate/stop endpoints can discard within a bounded policy rather than allocating arbitrary EOF bodies. Keep differing endpoint statuses and JSON policies outside the generic reader. Factor the transport capability rather than merging identity provider execution contracts.

Acceptance depends on N1 transport runtime only where shared owner adoption is desired; clients can be migrated independently behind existing methods. Validate CL/truncation/chunks/extensions/trailers/EOF/oversize/status secrecy against a library-backed fixture, and operation cancellation/child uncertainty. Existing stub tests that always produce CL replies are insufficient. Expect 450–700 framing lines removed but explicit deadline and domain wrappers retained; 3–5 days. Platforms, licenses and offline/build limits are the same as N1.

### N3 — setup Forgejo HTTP/TLS and N4 — provider HTTPS

[setup forgejo.rs](../../cmd/soda-setup/src/forgejo.rs) implements `forgejo_get_user/forgejo_revoke_token → forgejo_request → read_response/read_chunked/read_line`. The handwritten request path accepts only `http://`, even though origin input validation allows an HTTPS internal origin. It resolves one address and writes HTTP directly to TcpStream. Header reading has no byte cap, malformed CL can become EOF, and chunk-delimiter errors are ignored. Existing user ID/admin checks, scope/status handling and token secrecy are domain policy; transport restrictions and malformed framing acceptance are not.

REPLACE with existing ureq 2.12.1. `tools/release-assets/src/fetch/mod.rs::http_get` proves this locked blocking engine and rustls-backed TLS are already used in artifact acquisition. Use a separate Agent: no redirects, no inherited proxy environment unless deliberately configured, explicit connect/read/write/operation budgets, and normal certificate verification. Read both success and HTTP Status(error response) bodies via a cap+one `into_reader` adapter; retain required 200/204/status maps and neutral errors. Disable automatic body decompression unless its expansion is capped and intended; default ureq features include gzip. Do not silently bypass HTTPS verification to fix the source mismatch. [ureq 2.12.1 primary package documentation](https://docs.rs/crate/ureq/2.12.1).

ureq 2.12.1's AgentBuilder timeout, timeout_connect/read/write, redirects and try_proxy_from_env methods were inspected in the locally cached exact upstream source, along with its manifest (MIT or Apache-2.0; Rust 1.71). A builder timeout does not prove that a blocking DNS resolver can be cancelled or bounded at every stage. A focused stalled-resolver/connect/read check is required if the setup command's total deadline must include DNS; this investigation did not run it. ureq 3 custom transports were considered but not preferred: the current 2.12.1 resolution already fits TCP/TLS, while adopting an unstable custom Unix transport solely to avoid a small Hyper adapter would create a separate compatibility surface.

[host tcontrol_provider.rs](../../lib/host/src/tcontrol_provider.rs) `fetch_token/create_key → run_curl → Executor` already delegates HTTPS/TLS to mature curl; it does not implement TLS. `token_config/key_config/config_escape`, the status suffix decoder and process launch are redundant protocol plumbing, while `ProviderRequest`, credential redaction, OAuth/device/tag/key capability/lifetime validation are necessary. CONSOLIDATE this transport around ureq 2.12.1 with no redirects or unapproved proxy, Basic/Bearer authentication stored in headers rather than argv/logs, bounded response reading and the existing deadline/status/uncertainty maps. `token_form_body/query_escape` should use url::form_urlencoded::Serializer over deliberately ordered pairs. WHATWG form escaping has a different safe set from the custom `~` rule; endpoint-semantic equivalence for actual allowed tags is required, not the old exact query-byte oracle.

Do not bulk-delete every curl adapter. [acceptance coreos.rs](../../tools/acceptance/src/coreos.rs) `fetch_capped/curl_spec` uses the existing cancellation-owned process abstraction, HTTPS-only initial and redirect protocols, maximum five redirects, 60 s cap, temporary files/body bound and phase cancellation. RETAIN that library-backed HTTP engine and its small purpose adapter pending a demonstrated in-process cancellation design that also handles blocking resolver/workers. It parses status/header metadata for evidence, not HTTP body framing. The host provider adapter has a simpler facade and can adopt ureq without merging this lifecycle. Other resolved `ureq` asset fetchers remain library-backed owners; inspect redirect/root/proxy policy during their independent maintenance, rather than rewrite a complete engine already delegated to a library.

Independent RED01 caller challenge found a definite completion defect within this retained curl adapter: `coreos.rs::curl_spec` requests `%{http_code} %{url_effective}` with no final newline; `fetch_capped` waits, ignores the `join_pumps` error, and reads RedactingWriter buffers without closing either writer. `RedactingWriter::flush(false)` withholds the last unterminated URL line even with an empty secret set, and Process::join_pumps only joins/reports pump errors. Ordinary successful metadata is therefore withheld and the caller rejects the empty effective URL as unsafe. This is a source-derived, unexecuted defect, independently confirmed by network, persistence and root. Repair it before library migration: finish pump custody, propagate pump errors, close both writers and join sticky/final-flush errors, then parse completed buffers. RETAIN curl as the HTTP/TLS engine; RED01 owns this redactor lifecycle correction.

For N3/N4 acceptance: exercise current provider/user/token status matrices, credential bytes and unavailable/unconfirmed classifications, redirects and proxy leakage, TLS trust rejection, chunked/EOF bodies and caps after decompression, deadlines and no replay of uncertain key creation. Keep multi-provider credential/execution contracts intact. N3 removes roughly 100–180 lines over 1–2 days; N4 100–170 over 2–3 days, plus limited dependency exposure to runtime artifacts.

### N5 — rootfs pickup fixture stays in the candidate process

1. Validate a parsed HTTP request with tungstenite's server handshake/create_response before returning 101; don't use from_raw_socket as a substitute for handshake validation. Preserve application Origin/query/path/admission/slot checks.
2. Hold one stream/WebSocket state machine and drive socket readiness, output readiness, ping/pong/close, cancellation and monotonic deadlines in that owner. Preserve current message cap 131,072, first-request cap 4,096/5 s, JSON domain validation and binary rejection; configure bounded write buffering.

Flush the queue rather than resending the original message; preserve the returned frame only on WriteBufferFull. Read automatically queues protocol PONG/CLOSE, which must be flushed promptly. Drive closing until ConnectionClosed or a Soda close deadline.
4. Replace the detached expiry thread with the owner's monotonic timer after checked wall-clock expiry conversion. Explicitly cancel/join output work, close/kill/reap NativeAttach, shut down the socket and drop TerminalSlot/inflight only after final ownership resolution. There are two separate observed deadline defects:

- **Phase loses all finite child deadlines under an unbounded parent.** `Phase::child` computes `Some(Instant::now() + duration).min(self.inner.deadline)`.
