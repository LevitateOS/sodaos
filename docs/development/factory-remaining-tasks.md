#### Continuation and completion rule

After every completed item, lane, Muse goal or review, read this checklist and
continue the next ready unchecked item. A new Muse conversation at a released
boundary inherits this full objective. Keep the parent task active until FUX25;
local slice closure is not parent completion. Pending review does not block
independent ready work. Do not add a permission gate just because installation,
integration or a producer fix crosses a frontend file boundary.

Every open item must have either a concrete next action being advanced or a
specific missing prerequisite with its owner and needed action. A blocked item
does not stop independent work. User-owned authentication, unavailable external
access or an actual execution limit may require user action; explain the exact
blocker. Merely writing a plan, building assets or passing browser fixtures does
not finish the demo. Keep seeding/prepared-result runners stopped throughout.

The run pointer and monitor must point to this full checklist. A waker must not
interpret `frontend-ux-accepted` or an exited coordinator as whole-task completion.
It should continue remaining authorized work and report only meaningful progress,
failure, required user action or actual FUX25 completion. Scheduling stays human-owned.

This checklist is an implementation plan, not evidence of implementation or
permission to deploy, publish or start a new provider-funded Factory run. Use
the current task's actual authorization when executing it. Three independent JEV
consultations advised proving the app/host integration early; the dependency
ordering below also follows the observed app-origin, session and access gaps.
The judgments did not verify any implementation.

Each item is a task: **Needs** names prerequisite outputs, **Home** names the
existing implementation owner, and **Done** names the observable result. Where
an existing task already produces the required output, reuse it and finish only
the missing connection. Do not rebuild completed components or wait for an
entire historical parent to close. Use integration/browser/installed checks;
do not add unit tests. Source links in the journey blueprint provide the detailed
gap evidence. Check off a task only after its completion condition actually passes.
