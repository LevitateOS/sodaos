## Execution and completion rules

1. Dependencies below mean accepted inputs for integration, not a started worker. Disjoint preparatory/source work may start against an explicitly released contract; it cannot claim integration/native acceptance before its dependencies. The extra native release gates apply to runtime activation and qualification, not unrelated domain/Store/UI work.
2. A task progresses through source complete, serving integrated, focused checks passed, native/installed qualified where applicable, and independent acceptance. The central checklist records the actual stage; a helper-only result cannot close a serving task.
3. Each code packet names exact files, input hashes, producer→controller→transaction→effect→readback→next-stage callers, meaningful negative cases, resource owner, bounded verification budget and expected handoff. Shared schemas, manifests, result/assignment DTOs and Git/index operations have one writer and an acknowledged handoff. Keep active-command handles and 1–5-minute progress/deadline observations; do not duplicate a running command or grow a test suite to avoid diagnosing its failure.
4. Finish affected checks with each task. R47–R52 add cross-task and candidate qualification; they are not permission to postpone unit/transaction checks or repeatedly run broad suites. Use actual PostgreSQL for transactional claims; skipped database tests stay skipped.
5. Native proof precedes dependent runtime rewrites/full builds. Separate CLI jobs, synthetic checkpoints, renamed SDK tests, same-UID file permissions and fixture UI data cannot satisfy P1/P6/P7/P8/P9 or complete serving journeys. Failed design assumptions return with exact evidence to Codex for a bounded owner decision; workers cannot silently weaken the contract or choose a replacement architecture.
6. Keep one Muse coordinator, native workers, three implementation lanes maximum, canonical checkouts and no worktrees. Actual Contributor/XHIGH/model/account inheritance, command deadlines, release and source identity require evidence. A restricted terminal continuation is a capability block: preserve its handoff and use the supported reconciled owner route, not resend loops.
7. Finite provider/capacity/usage reservations precede calls; no provider runs under database locks. Source planning is not an authorization for paid calls, public release, deployment, broad cleanup or protected-appliance mutation. Existing specific authorizations remain in force; release approval is sought only when the concrete batch is reviewable.
8. Completion means current production wiring plus decisive evidence and independent acceptance, focused commits, truthful docs and released writers/resources. A precise external case remains open without blocking unrelated qualified core work. No percentage substitutes for this.
