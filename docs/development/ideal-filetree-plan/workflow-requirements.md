# Workflow requirements for the correctness and maintenance audit

This map executes the owner's requirements step against the application source
identified in the [current baseline](review-baseline.md#current-input-baseline-2026-10-07),
with baseline commit `5b0ff834` and canonical final-key decision
`929c9a38df45e7b796dee8080d33512be78d7b1c` recorded during this step. It maps all 80 existing slices into 31 product workflows
and six crosscutting support contexts. It does not establish current source
validity, implementation of the target factory or installed qualification.

The cited subject owners define requirements under the
[documentation authority rules](../../README.md#authority-rules). This is an
audit crosswalk, not another product specification. Product/trust documents own
the intended model; references describe current interfaces; research, source,
tests and earlier cards provide evidence rather than new product authority.
Current user decisions control conflicting guidance. A required external producer
below is not a claim that its target SDK method exists or was exercised.

Current implementation chains and bounded finding dispositions are recorded in
[connected workflow traces](workflow-traces.md). This link does not advance the
requirements extraction or its historical source review.

## Common requirements and their authority

- Repository policy, appliance capacity, provider sponsorship, browser admission,
  run execution and native publication/merge are separate grants. A parser,
  transport, saved ID or successful observation grants none of them.
  [Trust](../../architecture/trust.md#distinct-authorities).
- Project lifecycle preserves retained roots, human work and service volumes;
  factory cleanup releases recorded run-owned resources. Obsolete experimental
  artifacts do not justify permanent compatibility code or deletion of protected
  current state. [Projects](../../product/projects.md#persistence),
  [scope](../../product/scope.md#retire), [AGENTS](../../../AGENTS.md).
- Requested effect, observed effect and confirmed completion are distinct.
  Uncertain native mutations require operation-specific reconciliation;
  unconfirmed termination/credential return prevents reuse. Cancellation cannot
  erase committed effects or imply successful cleanup.
  [Outcomes](../../architecture/trust.md#outcomes-failures-and-retries).
- Configured deadlines, bounds, trust admission, raw fingerprints and original
  signed-byte custody remain required at their callers. These requirements do
  not mandate one numeric budget, parser profile, output layout or runtime bridge.
  [Release](../../architecture/release.md), [support](../native-support.md).
- The automatic factory is the intended product. The current operator command
  remains a narrower interface, not a second permanent execution model. Local
  Soda CI execution, extra Project profiles, hostile-tenant isolation and general
  recovery orchestration stay deferred. [Product](../../product/overview.md#factory-operating-rules),
  [current interface](../../reference/factory.md), [scope](../../product/scope.md).

## Admission and compatibility dispositions

These classifications guide later integration review; they are not removal
instructions. Preserve current caller contracts and explicit owner decisions.
Tests may demonstrate a representation without making it normative.

| Behavior/profile | Authority and disposition |
| --- | --- |

Trace each schema/caller before deciding alias order, null coercion, bytes, numeric tokens or output ordering; the retired binder's entire behavior is not a universal requirement.
