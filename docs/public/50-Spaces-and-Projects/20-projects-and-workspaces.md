# Projects and workspaces

A Project is the persistent shared development environment for one native repository. People and Factory work use the same Rocky headless Project root, with separate Linux accounts, checkouts and execution identities.

The human owner of a repository creates its Project from that repository's settings. Organization-owned Project creation is unsupported. Creation reserves and starts the repository's Project; it does not Join the creator or any teammate, clone the repository, or enroll an AI provider. If the Project already exists, inspect and reuse that reservation instead of creating another environment. If a create request has an uncertain result, return to the same repository settings and inspect its Project state before trying again.

To work in the environment, each person uses the native Forgejo account that will own their access. Choose **Join project** for that repository. Join requires current native code-write permission. It creates a Project-local Linux account and records membership only after native account provisioning succeeds. Join can be account-only; external SSH keys are optional. A read-only repository grant, public visibility, prior membership, or Soda operator status does not grant execution access. If Join is denied, ask the repository owner to grant code-write access, then retry from the original Project. Do not create a second Project to work around a permission failure.

The Project keeps the member's original Linux login bound to their stable native identity. A native username change or repository transfer does not rename or remap the Linux account, file ownership, or installed SSH keys. Different members have separate homes and checkouts; shared tools, files and explicitly assigned services remain within the common Project. See [Shared tools and files](../60-Develop/30-shared-tools-and-files.md) and [Project services](../60-Develop/40-project-services.md).

Start and Stop act on the persistent Project root. Start reuses the retained root and its homes, installed tools, files and service volumes. It does not revive a terminal process, Factory conversation or prior credential lease. Stop coordinates Factory withdrawal and affects every member using the Project: live terminals, SSH connections and services are interrupted while persistent data remains. Coordinate with other users before stopping. To continue later, explicitly Start the same Project and open a new terminal or execution as needed.

Human Project creation and joining do not prepare a Factory checkout. Before Factory work begins, the repository's exact setup inputs must be accepted, an administrator must inspect and provide shared prerequisites, and unprivileged coder and reviewer readiness must be established. Changed setup inputs invalidate affected readiness; maintenance holds pause affected work until checks run again. Follow [Prepare a Project for Factory work](30-prepare-project.md) for that separate process. Provider enrollment and Factory sponsorship are also separate; see [Provider connections](../30-Set-up/40-provider-connections.md) and [Factory authorization](../40-Factory/20-factory-authorization.md).
